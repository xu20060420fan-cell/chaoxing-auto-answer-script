### 2.3 发现的一处真实失效（已修）

**新版章节目录页换了结构**（`/mooc2-ans/mycourse/studentcourse`）：

```html

  <div class="catalog_title" role="link">
    <div class="catalog_name newCatalog_name"><a class="clicktitle">…</a></div>
```

- 目录页**没有** `onclick="getTeacherAjax"`（脚本策略 1 落空），

### 2.4 关于 `isStudyInterface()` 的一处澄清

脚本原判定是 `pathname.indexOf('/mycourse/studentstudy') === 0`（锚定匹配）。
实机学习页 pathname 就是 `/mycourse/studentstudy`，**原判定本来能命中**，不存在"脚本整体不启动"的线上故障。

但上游 OCS 5.2.1 显式处理了 `mooc-ans/mycourse/studentstudy` 这类带前缀的变体（部分院校/版本会这么发），
因此已把判定放宽为**子串匹配** `/\/mycourse\/studentstudy/`（与 OCS 口径一致）。
这属于**防御性加固**，不是修线上故障 —— 这一点已在代码注释里写明，不夸大。

### 6.3 本轮新发现并已修的两个问题

**问题①：超星作业的选项被重复收集 → 给 AI 的选项表污染（答题准确率直接受损）**

`<li class="clearfix">` 和它内部的 `<i class="fl">A、</i>`，`textContent` **都**以 "A、" 开头 →
`extractOptions` 方法1 把两者都收进来 → 4 道选项变成 8 条。实际喂给 AI 的 prompt 是：

```
  A. 00090H～00091H
  A. 
  B. 00090H～00093H
  B. 
  C. 00096H～00099H
  C. 
  D. 00096H～00097H
  D. 
```

后果 ①：一半是空行，干扰模型判断；
后果 ②：`fillAnswer` 的"文本相似度匹配"分支会拿 AI 的答案去和这些 text 比，
`clearString("A、")` 之后等于 `"a"`，与 AI 回答的 `"A"` **完全相等（相似度 1.0）** →
会命中那条只有字母的 `<i>` → `tryClickOptionElement(<i>)` 点了个寂寞 → **选项根本没被选中，但日志却显示"已选择选项 A"**。

→ 已修：新增 `normalizeOptions()`，同一字母只保留内容最完整的一条；
内容为空（只有字母标记）时改用可点击的 `li/label` 容器作为元素；最后按字母排序。

**问题②：任务点 iframe 没有 `data` 属性 → 已完成视频被原地重播（刷课进度缺口）**

`readCardJobId()` 靠 iframe 的 `data` 属性（JSON 里的 `jobid`）来把 DOM 里的视频卡片和 `attachments` 对上号。
当前学习通的任务点 iframe **没有 `data` 属性**（只有 class + src），
于是 `readCardJobId` 返回 null → `iframeJobDoneStatus` 返回 null →
`isVideoTaskDone` 返回 null → 脚本按注释里的"判定不了时保守视为未完成"处理 →
**平台上已标记完成（`job` 已消失）的视频会被重新播一遍**（正是 2026-09 那次修复想解决的老毛病）。

→ 已修：给 `isVideoTaskDone` 加了一层 `attachments` 兜底（新增 `attachmentsMediaState()`）：
当 `iframeJobDoneStatus` 判不出来时，若本章节 `attachments` 里**已没有未完成的音视频任务点**
（`job` 为假且 `isPassed !== false`），就判定该视频已完成、不再重播；
attachments 取不到 / 本章没有音视频时仍返回 null（判不了 → 保守），**不改变原有行为**。

### 6.4 本轮无法在真机上直接验证的两点（如实标注）

1. **任务点 iframe 的 `data` 属性到底有没有**：
   内置浏览器的 `inspect` 动作会过滤 `data-*` 属性，`query(kind=dom)` 又会跳过 iframe，
   两种取法都读不到 iframe 上的 `data`。
   旁证：**上游 OCS 5.2.1（2026-10 最新版）用的是完全相同的取值链**
   （`win.frameElement.getAttribute('data')` → `win.frameElement.contentWindow.parent.frameElement.getAttribute('data')` → `frame_data.jobid || frame_data._jobid`），
   两者不可能同时失效；且问题②的兜底已把对该属性的依赖降到"锦上添花"。
2. **作答页的 `saveQuestion` 保存按钮**：该按钮只出现在可作答页，
   而本账号两门课的作业都已提交，无法在不点"重做"（会清空已有作答记录）的前提下验证，故未验证。

## 七、学习通「多视频轮流播放 / 漏视频」专项（2026-10-23，v2.8 → v2.9）

### 7.1 现场实机取证

用户点到了有多个视频的章节（毛泽东思想概论 / 1.4 红色歌曲，**16 个待完成任务点**），实机确认：

- 学习页 `chapterId=422117598`，左侧目录 `1.4 红色歌曲 16`；
- **knowledge/cards 是一个 9911px 高的单个 iframe**，整章 16 个任务点卡片全部同时渲染，
  每个卡片再套一层自己的 videojs 播放器 iframe（`ans-attach-online ans-insertvideo-online`，
  里面 `div#video.video-js > video#video_html5_api`），
  每个卡片都带「● 任务点　完成条件 | 观看时长需 ≥ 总时长的 90%」；
- 任务点卡片 iframe **没有 `data` 属性**（只有 class + src）。

### 7.2 根因（脚本侧 3 处，互相叠加）

| # | 位置 | 问题 |
|---|---|---|
| ① | `pickMediaToPlay` 顺序模式 | 每轮都"从 DOM 里挑第一个 paused 的视频"，**完全不记进度** → 平台切到第 2 个后，脚本下一轮又回到第 1 个 |
| ② | `setupStudyFrameWorker` + `attachVideoPauseRecovery` + `HTMLMediaElement.prototype.pause` 重写 | 学习通整章 N 个播放器 iframe **同时存在**，每个 iframe 里的 worker 都想把"自己 iframe 里的视频"拉回来；`pause` 还被全局吞掉，平台连"切任务点时暂停旧视频"都做不到 → 旧视频停不下来，新旧同播，脚本再按①去挑 → **轮流播放** |
| ③ | `readCardJobId` 依赖 iframe 的 `data` 属性 | 当前平台没有该属性 → `isVideoTaskDone` 恒返回 null → **已完成的任务点被当成未完成** → 看完的又被重播、且识别不出该播哪个 |

### 7.3 修法（v2.9）

| 改动 | 说明 |
|---|---|
| **播放队列 + 只进不退的指针** | 新增 `ensureMediaSeq` / `advanceMediaSeq` / `mediaSig` / `sameMediaList`。队列按任务点顺序建立，指针播完一个才 `++`，**绝不回头**；平台重建卡片 DOM（视频元素被换掉）时，按**视频地址**（objectid 稳定）把指针对齐回同一个任务点，而不是跳回第一个 |
| **目标视频互斥** | 新增 `markTargetMedia` / `isTargetMedia`，把"当前唯一要保护的视频"写到 `window.top.__aa_targetMedia`。① worker 只恢复目标视频；② pause 事件恢复只处理目标视频；③ `HTMLMediaElement.prototype.pause` 重写**只拦目标视频**，其余视频一律 `origPause` 放行 → 平台能正常切任务点 |
| **按地址精确匹配任务点** | 新增 `attachmentForMedia`：从视频地址里取 objectid（`.../03/f7/ca/<objectid>/sd.mp4`），去 `attachments[].property.objectid` 里精确匹配（平台自己的 `mooc-ans/js/resource_scan.js` 就是这么读的）→ 能准确知道"这个视频的任务点做完了没" |
