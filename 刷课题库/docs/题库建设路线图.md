# 刷课题库建设与维护路线图

> 2026-10-24 更新（脚本 v2.10 接入站点后端后）。下方"现状"部分已落地。

## 1. 核心目标

- **准确率优先**：宁可少答一题，也不能把错误答案写进题库。
- **文本答案优先**：题库存选项文本而不是字母，避免选项顺序打乱导致选错。
- **题库 + LLM 双路**：选择/判断优先走题库，填空/简答/论述题 fallback 到 LLM。
- **可持续沉淀**：脚本在已批阅页面读到平台答案时自动回写，题库会随使用量变大。

## 2. 题库来源（按优先级）

| 优先级 | 来源 | 状态 | 操作方式 |
|--------|------|------|----------|
| 1 | 脚本判分自动沉淀 | ✅ 已实现 | 脚本读到平台答案 → 回写**沉淀池** → 管理员审核 → 晋升公共池 |
| 2 | 外部题库（星夜等） | ⏳ 待配置 | 脚本面板粘贴 OCS JSON；服务端填 `data/remote-sources.json` |
| 3 | 自采（自己课程） | ✅ 工具就绪 | `repos/学习通题目导出.user.js` 导出 JSON → `node import.js 文件.json json --remote <站点> --key <口令>` |
| 4 | 公开期末复习资料 | ✅ 工具就绪 | 整理成 CSV 后用 `npm run import` 导入 |
| 5 | 抓包第三方脚本/APP | **仅允许自己分析协议，不提供破解代码** | — |

## 3. 关键改造点（均已实现）

### 3.1 脚本端：选项顺序无关的答案映射

题库存**选项文本**而不是字母，答题时按当前页面的选项顺序映射回字母
（`lib/matcher.js` 的 `mapAnswerToLetters`）。

### 3.2 脚本端：题库无命中时 fallback 到 LLM

选择/判断优先走题库；填空/简答/论述题 fallback 到 AI（脚本端 13 家大模型 + 搜题兜底）。

### 3.3 脚本端：判分后回写题目（v2.10 新增）

`collectMarkedAnswers()` 在已批阅的作业/考试页上：

1. 用 `.mark_answer .rightAnswerContent` 取结构化答案；
2. 失败则回退到不依赖 class 的文本锚点「正确答案 / 参考答案」；
3. 题干与选项**复用** `detectQuestions()` 的结果；
4. POST 到 `{站点}/tiku-api/api/pool` 进沉淀池。

### 3.4 服务端：沉淀池 + 质量闸（v2.10 新增）

- 公开回写端点不靠密钥（脚本公开，密钥藏不住）→ 靠**质量闸 + 限流 + 不参与匹配**防污染；
- 入库前校验：题干长度、题型合法、选项非空不重复、答案字母在选项范围内、单选/多选答案个数；
- 管理员审核（`/api/pool/promote`）后才晋升公共池。

## 4. 导入格式

CSV（制表符分隔）：

```
question    options           answer        type   source
TCP协议位于哪一层？  物理层,数据链路层,网络层,传输层  传输层  single  计算机网络
```

JSON：导出工具的原生格式，直接 `--remote` 推。

## 5. 准确率保障规则

- 题型跨界保护：判断/填空题不会被选择题题库命中。
- 次优答案冲突检测：若最优与次优答案在阈值内并列，直接弃答。
- 选项顺序无关：题库只存文本答案。
- 沉淀池不参与匹配：脏数据污染不到任何人。
