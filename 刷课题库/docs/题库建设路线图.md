# 刷课题库建设与维护路线图

## 1. 核心目标

- **准确率优先**：宁可少答一题，也不能把错误答案写进题库。
- **文本答案优先**：题库存选项文本而不是字母，避免选项顺序打乱导致选错。
- **题库 + LLM 双路**：选择/判断优先走题库，填空/简答/论述题 fallback 到 LLM。
- **可持续沉淀**：每次答题成功都把题目回收到自建题库，题库会越用越大。

## 2. 题库来源（按优先级）

| 优先级 | 来源 | 操作方式 |
|--------|------|----------|
| 1 | 脚本运行日志沉淀 | 已提供 `tools/log2tiku.js`，答题成功后 POST 到 `/api/collect` |
| 2 | 公开期末复习资料 | 整理成 CSV 后用 `npm run import` 导入 |
| 3 | MOOC 讨论区/百度文库/学校公开资料 | 清洗后批量导入 |
| 4 | 第三方授权 API | 购买/授权后接入 `tikuList` 多源题库 |
| 5 | 抓包第三方脚本/APP | **仅允许自己分析协议，不提供破解代码** |

## 3. 关键改造点

### 3.1 脚本端：选项顺序无关的答案映射

脚本当前题库存的是字母答案，必须改成存文本答案，然后在答题时按当前页面选项顺序映射为字母。

```js
function findAnswerLetters(options, answerTexts) {
  const ansSet = new Set(answerTexts.map(a => a.trim()));
  const letters = [];
  options.forEach((opt, idx) => {
    const letter = String.fromCharCode(65 + idx);
    if (ansSet.has(opt.text?.trim())) letters.push(letter);
  });
  return letters.sort().join('');
}
```

### 3.2 脚本端：题库无命中时 fallback 到 LLM

```js
async function queryTikuOrLLM(question, options, type) {
  const tikuAnswer = await queryTiku(question, options, type);
  if (tikuAnswer) return tikuAnswer;

  if (['填空题', '简答题', '论述题'].includes(type)) {
    return await queryLLM(question, type);
  }
  return null;
}
```

### 3.3 脚本端：答题成功后回写题目

```js
async function collectQuestion(question, options, type, answer) {
  try {
    await fetch('http://localhost:8092/api/collect', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ question, options, type, answer, source: '脚本自动沉淀' })
    });
  } catch (e) { /* 静默 */ }
}
```

## 4. 导入格式

CSV（制表符分隔）：

```
question    options           answer        type   source
TCP协议位于哪一层？  物理层,数据链路层,网络层,传输层  传输层  single  计算机网络
```

## 5. 准确率保障规则（已在服务中实现）

- 题型跨界保护：判断/填空题不会被选择题题库命中。
- 次优答案冲突检测：若最优与次优答案在阈值内并列，直接弃答。
- 选项顺序无关：题库只存文本答案。
